# 模块设计参考与通用改进

从已审查源码的功能设计看，墨鱼的微博净化适合作为功能参考：分别处理开屏预加载、实时开屏、信息流、搜索、详情、评论和视频，利用明确的广告标记筛选部分内容，也提供精简选项。原作者及其基于 zmqcherish 的声明保留在原始脚本中。这是源码评价，不是当前微博版本的手机效果排名。

该模块也有边界：入口通过正文正则提取 JSON 后解析，不能据此保证异常响应或所有新接口都兼容。可莉近期明文插件的逐接口 jq 处理方式适合作为结构参考；奶思的应用拆分方式有利于单独维护。不同 App 的字段、开屏缓存、协议和签名不同，不能复制一套广告字段到所有 App。

转换流程现统一加入以下处理：

- jq 报错、无输出或产生多份输出时返回原 JSON；成功产生一份结果时保留作者的处理结果。
- 相邻、主机匹配范围一致、响应内容或脚本参数完全相同的绑定可合并匹配范围，减少重复执行候选。
- 不跨越不同处理者合并，不合并含数字或具名反向引用的正则，避免改变优先级和捕获含义。
- 不将不同主机的绑定合为一项，便于金融和必要业务保护分别处理。
- 原始插件档案、脚本字节、默认参数和作者声明仍保留。修改转换输出不等于修改作者原始档案。

通用改进不替代逐应用检查：同域广告与正常内容仍需对应接口逻辑；不同脚本或不同 jq 的重叠需要单独确认；登录、订单、支付、错误响应及开屏倒计时需要实际设备和脱敏响应验证。

检查入口为 `curated/tools/test_module_quality.py`。当前个人配置的严格处理链检查与公共资源检查分别记录，公共检查通过不代表个人配置的全部处理链或真机效果已通过。完整合集在逐应用交付模式中保持关闭备用。
