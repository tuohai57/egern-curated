# Egern 2.22.0 维护版资源

本目录在原仓库上增补维护资源，保留原镜像和原作者来源。

当前生效来源排除可莉（kelee）原插件、镜像和加密 Loon 脚本。铁路12306、网易邮箱大师、小黑盒、美颜相机、大麦及微信公众号采用自主明文重写；拼多多首页同样改用自主脚本。实现范围以清晰可检查的接口与字段为准，并未复刻不可见的加密实现或承诺其全部功能。其余模块主要采用 FMZ / Maasea 的可检查方案。

自主源码见 `scripts/source/rewritten-apps.js`，发布依赖仍以内容哈希命名。对已识别广告接口，只重置已存在的计时字段、清理已知广告集合，保留响应外层、正常帖子、票夹、订单、普通工具及相机功能。未识别结构和登录/服务错误保留原文；客户端缓存和写死倒计时仍需要设备验证。

- `modules/managed/`：逐 App 的 Surge 兼容模块；Egern 官方 FAQ 支持通过 URL 添加 Surge 模块。
- `scripts/managed/`：脚本依赖快照，以内容哈希命名；模块更新后才切换新依赖。
- `rules/managed/`：去重后的 Egern 原生远程规则集。金融、必要服务和 App 父子域例外在个人主配置前置。
- `managed-manifest.json`：原模块、原脚本 URL/哈希、维护版哈希、修改记录及 MITM 主机。
- `managed-rules.json`：规则来源与实际成员；`managed-protection.json`：金融/必要服务保护域。
- `tools/check_managed.py` / `tools/test_scripts.cjs`：公开资源检查与 JavaScript 离线样例；GitHub Actions 在推送时运行。

模块去广告与通用广告域集共同工作。模块负责开屏配置、信息流插入卡、横幅和推广功能精简；域集拦独立广告服务。模块不附带整域 REJECT，避免高于主规则的拒绝破坏金融和正常业务。每个 App 只选一套响应处理来源；相同 URL 的多条 jq 操作合并。

维护版保留源脚本主要净化能力，修复重复脚本名、未定义参数、缺失解密主机和可确认的脚本错误；保留银行、支付、推送、订单和安全中心相关能力。JSON 脚本在非 JSON、HTTP 错误和异常结构下原样放行；微博开屏 JSON+OK 格式单独兼容。无法凭静态检查保证新版 App 的所有业务行为。

更新间隔由个人 YAML 的 `update_interval: 86400` 控制。主配置需保留细分 App 组、金融例外、DNS 和 MITM 排除。仓库不发布含订阅/节点密码的个人 YAML，也不生成或发布 CA 私钥。

HTTPS 改写需要 Egern 开启解密、手机安装并完全信任用户自己的 CA。当前测试是离线样例和来源完整性检查；没有 Egern/iOS 真机认证。二进制/protobuf、缓存开屏、客户端写死倒计时仍需真机验证，不能将“模块已加载”当作“所有广告已消失”。

上游更新应先下载、复核差异、修复、运行完整配置的去重/遮蔽/DNS检查，再发布。公开仓库 CI 是发布后的复核，不会自动放行或自动合并未经审阅的上游变化。手机远程资源能更新，但新增组、节点、DNS转发表和新增主配置排除项仍需重新导入个人 YAML。
